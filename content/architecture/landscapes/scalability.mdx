This landscape is a **catalog of scale hops**, not a 65th lesson. The explorer already shows ingress, compute, cache, and primary. Module 2 names which of those hops are **synchronous**, which are **optional**, and which **amplify writes**.

Authoritative vs derived:

- **Authoritative:** the chosen primary (PostgreSQL default, DynamoDB alternative) and any uniquely constrained write path (TokenX ledger terminals).
- **Derived:** L4/L7 balancer membership, Kubernetes replica counts, Redis, read replicas, CDN, fan-out timelines, autoscaler metrics.

Synchronous edges: client → DNS → balancer → gateway → app → primary (or cache on a read hit). Asynchronous edges: replica apply, outbox, Kafka, autoscaler decisions. Autoscaling does not fence a writer and does not repair split-brain.

### What fails independently

Balancer membership or a draining pod can fail while the authoritative store still **accepts or rejects correctly**. A VIP that dropped a node, a Kubernetes replica in Terminating, or an autoscaler that has not yet added capacity is a derived hop: it can 502, shed, or retry-amplify without promoting a lagging replica as the writer.
